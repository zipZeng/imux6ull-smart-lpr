# 定位算法

定位代码在 `client/src/PlateDetector.h` 和 `client/src/PlateDetector.cpp`。它只依赖 OpenCV，头文件里不能出现 Qt。入口是 `locatePlate(一张 BGR 图)`，输出零到三个框、裁好的车牌小图，以及边缘图、二值图、闭运算掩码。它不读摄像头，也不知道 RTSP。拉流时由 `DetectThread` 调用，选图时由 `MainWindow::onSelectImage()` 在主线程调用。窗口上的控件和线程见 [架构设计.md](架构设计.md)。

国内小型汽车蓝牌大约 440 mm × 140 mm，宽高比约 3.14。算法抓住三件事：字符有很多竖笔画、牌底是蓝色或黄色、整体接近一块横向矩形。侧着拍、夜里反光、车身也是蓝色时，这三件事不会同时成立，所以有几条互补的找牌路径。不做字符识别，也不用深度学习。

开发板送来的实时画面是 640×480。`samples/` 里的实车图是 720×1160。两边都调用同一个 `locatePlate()`。选图或定位成功时，右侧文字是「检测到车牌」，数字用得分最高的那一张；没找到时是「未检测到车牌」。多张候选全部画在左侧。

## 一次定位怎么走

`locatePlate()` 先检查 `cfg` 是否自相矛盾（高斯核必须是奇数、宽高比上下限不能反了），再拒绝空图和宽高小于 32 的图。然后按这个顺序调用本文件里的函数：

| 函数 | 作用 |
| --- | --- |
| `preProcess()` | 灰度、高斯、垂直 Sobel、二值化、开运算、闭运算 |
| `getPlateContours()` | 在边缘掩码上按正对矩形筛选 |
| `keepPaintedPlates()` | 框里蓝/黄不够就丢掉，用来挡住车标和镀铬字 |
| `plateColorMask()` 再进一次 `getPlateContours()` | 字符没连成整块时，补一块水平实心牌 |
| `findTiltedColorPlates()` | 侧拍、小牌：按旋转矩形找蓝/黄块 |
| `findTiltedEdgePlates()` | 夜间、蓝车身：按字符边缘找旋转矩形 |
| `suppressOverlap()` | 重叠的只留分高的，最多 3 个 |
| `drawAndCropPlate()` | 裁出车牌小图。界面上的红框不用这里画的绿框 |

`found` 表示至少有一张 ROI。颜色检查可能把几何上合格的框全部删掉，那时 `found` 仍是 false。

四路候选放进同一个数组，再按得分做重叠抑制。两个框的 IoU 超过 0.30，或者低分框的中心落在高分框向四周扩 1/5 的范围内，只留分高的那个。

文件内部还有一组不进头文件的辅助函数，写在匿名命名空间里。界面调用不到它们。对外的结构体只有 OpenCV 类型：`PlateCandidate`（一个框）、`PreprocessResult`（中间图）、`LocateResult`（一次检测的全部结果）、`FilterStats`（轮廓因为面积、尺寸、宽高比、矩形度、倾斜或边缘被丢掉多少）。

## 预处理

`preProcess()` 的输入可以是灰度、BGR 或 BGRA。图宽或高小于 32 直接拒绝。

1. **统一成灰度。** 定位先不看颜色，颜色留到后面专门筛蓝底、黄底。3 通道走 `BGR2GRAY`，4 通道走 `BGRA2GRAY`。
2. **高斯模糊，核 5×5。** 减弱树叶、地面颗粒这类细噪点。核越大，字符笔画也越糊。
3. **垂直 Sobel，`dx=1, dy=0`，核大小 3。** 只响应左右方向的亮度跳变。汉字和字母的竖笔画会产生很强的响应，车身大面积平滑区域几乎没有。先用 `CV_16S` 保留正负梯度，再用 `convertScaleAbs` 收成 0～255。水平方向的车缝、路沿在这张图上会弱很多。
4. **二值化。** 默认大津法。大津结果低于 25 时，说明边缘图几乎全黑，改用固定阈值 80，避免整张图变成噪点。
5. **3×3 开运算。** 擦掉孤立小白点，免得后面的闭运算把噪点也粘成一块。
6. **闭运算，核大约 17×5，做 1 次。** 核是扁的：横向跨度大，才能把左右相邻的字符补成一条；纵向跨度小，才不容易把车牌和车标、保险杠粘在一起。核宽按图像宽度相对 1000 像素缩放，限制在 0.7～1.5 倍，并强制成奇数。720 宽的样图实际核大约是 13×5。

输出里最重要的是 `mask`。正对轮廓在这张图上找。`edges` 留给调试窗口，也用来看候选框里面的平均边缘强不强。

## 正对的边缘轮廓

`getPlateContours()` 在掩码上找外轮廓（`RETR_EXTERNAL`，只要最外层）。`findContours` 会改输入图，所以先 `clone`。对每个轮廓：

1. **面积。** 同时看绝对像素和占整图的比例，取更严的那一侧。太小的是噪点或单个字符，太大的是车身、地面。绝对面积至少 800，比例至少 0.15%、至多 20%。
2. **外接矩形尺寸。** 宽至少 60、高至少 18，宽不超过图宽的 80%，高不超过图高的 55%。
3. **宽高比 = 宽 / 高，必须在 2.0～5.5。** 标准蓝牌约 3.14。这里用的是不旋转的外接矩形，明显侧拍的牌往往在这里被淘汰，交给后面的旋转框。
4. **矩形度 = 轮廓面积 / 外接矩形面积，至少 0.40。** 闭运算之后边缘是毛糙的，不要求一定是四边形。矩形度太低说明笔画是断开的，或者是一条弯边。
5. **倾斜角不超过 20°。** `minAreaRect` 的角度定义别扭，范围大约在 -90°～0°。`longEdgeTiltDeg()` 先判断哪条边是长边，再折成「长边相对水平线歪了多少」。正对路径只接受接近水平的牌。
6. **边缘均值至少 12。** 在原边缘图上取这个矩形的平均亮度。没有字符的横条、纯色反光在这里丢掉。

得分大致是：宽高比越接近 3.14 越高（权重 0.55），矩形度越高越好（0.30），边缘越强越好（0.15，超过 40 就封顶）。这一步还没加上颜色分。

`platePaintRatio()` 把矩形裁出来，转到 HSV，统计落在蓝色或黄色范围内的像素比例。边缘路径用的蓝比实心颜色块松：色相 95～140，饱和度至少 50，亮度至少 40。黄是色相 10～40，饱和度和亮度至少 70。`keepPaintedPlates()` 在边缘路径上要求占比至少 0.18。通过的候选把 `0.25 * 颜色占比` 加进得分。

本田车尾的镀铬 “CITY” 竖线很多、形状也像一块牌，但几乎没有蓝底，就在这里被丢掉。蓝色现代那张正对的牌走通的是这一条。

## 水平颜色块

字符间隙太大、闭运算没把整块牌粘上时，边缘路径会只看到半块牌或什么都看不到。`plateColorMask()` 先把蓝底、黄底涂成白色，再闭运算把白字留下的洞补上，然后仍调用 `getPlateContours()`。

这一路的蓝是色相 100～140、饱和度至少 80、亮度至少 50；黄是色相 15～40、饱和度至少 80、亮度至少 80。闭运算仍用 17×5 的矩形核，再用 5×5 开运算擦掉细碎蓝点。回来之后还要删掉太窄（宽小于 110 或高小于 36）、太宽（超过图宽 65%）、贴在图像最顶上的块。颜色占比至少 0.60。正对本田那张牌走的是这一条。

## 倾斜颜色块

车是侧着拍的时候，一个 3:1 的牌子转 20° 以后，水平外接矩形的宽高比会掉到 2.0 以下，前两条路径会把它判掉。`findTiltedColorPlates()` 改用 `minAreaRect`，量的是旋转之后的长边和短边。

颜色范围和水平颜色块一样，形态学改成 11×11 椭圆闭运算再加 5×5 椭圆开运算。椭圆核不会强行把块拉成水平条。然后要求：

- 面积在绝对下限和「不超过 8 万像素、也不超过图面积 8%」之间。
- 旋转后的长边至少 100 像素，不超过图宽的 48%；短边至少 28。
- 长边 / 短边在 1.55～4.8。1.55 比正对路径的 2.0 低，因为小牌和强透视会让旋转矩形变胖。丰田那张小牌大约是 1.66。
- 矩形度至少 0.55，比正对路径更严。
- 在旋转矩形内部再数一次原始蓝/黄像素，至少 55%。
- 外接矩形的顶边 `y` 必须大于 12，用来丢掉挡风玻璃上沿的蓝色反光。
- 边缘均值至少 8。倾斜牌的笔画在垂直 Sobel 上会弱一些。

四个角点存进 `PlateCandidate::corners`，`hasCorners = true`。界面看到这个标志就画四边形。远处丰田小牌、别克、大众、金色轿车走的是这一条。

## 倾斜边缘块

夜里尾灯一照，蓝底饱和度下降，颜色掩码是碎的。车身本身是蓝色时，颜色掩码又会把车牌和保险杠吞成一大块。`findTiltedEdgePlates()` 改去更高阈值的字符边缘上找旋转矩形，同时仍要求这块里面有一些蓝或黄。

输入是预处理的边缘强度图，不是已经用大津切过的二值图。函数自己再二值化一次：阈值取「大津结果」和 60 里更高的那个。夜间照片的大津阈值可能只有十几，整张图会变成白花花的一块。固定一个 60 的下限，字符还在，大片弱反光被压掉。

后面同样是 3×3 开运算，再用扁核做闭运算。筛选比颜色旋转框松在实心程度上（矩形度只要 0.32），严在形状和边缘上：

- 宽高比 2.0～5.2，倾斜不超过 42°。
- 长边至少 100，不超过图宽的 45%。
- 框内边缘均值至少 18。
- 用更松的蓝/黄范围再量占比，至少 32%：蓝的饱和度、亮度只要 35。夜间牌的蓝色被灯光洗淡了，用「饱和度至少 80」会量成 0。
- 框不能贴在图像左边缘或右边缘（左右各留 2 像素）。顶边同样要 `y > 12`。

这条路径的得分权重较低。颜色路径已经找到的同一块牌，合并时会被删掉。夜间奥迪和蓝色沃尔沃走的是这一条。

## 合并、裁剪

`suppressOverlap()` 按得分排序。保留一个候选之前，看它和已经留下的框：IoU 大于 0.30，或者它的中心落在对方框向四周扩大 1/5 的范围内，就认为是同一张牌。最多 3 张。两个框只有一条边挨着时 IoU 很小，不会被当成重复。中心包含是为了处理「一个小框完全落在大框内部，但 IoU 不到 0.30」的情况。

`drawAndCropPlate()` 里，正对候选把矩形每边外扩 8 像素，再和图像边界求交，`clone` 出 ROI。倾斜候选把四个角从中心向外乘 1.08，`warpPlate()` 按 y 分成上下两边、再按 x 分成左右，得到左上、右上、右下、左下，用 `getPerspectiveTransform` 和 `warpPerspective` 拉成横着的小图。若结果高度大于宽度，再 `ROTATE_90_CLOCKWISE`。界面右侧显示的是得分最高的那一张。

算法内部的标注图是绿色框，放在 `LocateResult::annotated`。界面不显示它，红框由 `MainWindow::paintPlates()` 用 `QPainter` 另画。OpenCV 自带的 Hershey 字体不能画中文，所以标注图上只写 `Plate 1` 这种英文。

其它小函数：`ensureOdd()` 把核尺寸收成不小于下限的奇数；`validateConfig()` 在检测前检查参数范围；`rectIou()` 算两个轴对齐矩形的交并比。

## 界面怎么把图交进去

选图时 `QImage::load()` 读文件，`qImageToBgr()` 转成 BGR 再交给 `locatePlate()`。拉流时 `CaptureThread` 读到的已经是 BGR，`onFrame()` 显示前才做 `COLOR_BGR2RGB`。

| | QImage | cv::Mat |
| --- | --- | --- |
| 彩色通道顺序 | `Format_RGB888` 是 R、G、B | 彩色默认 B、G、R |
| 一行占多少字节 | 常常按 4 字节对齐，`bytesPerLine()` 可能大于宽 × 3 | 用 `step` 表示下一行从哪里开始 |
| 谁拥有内存 | `QImage` 销毁后 `bits()` 作废 | `Mat` 是引用计数，拷贝构造默认共享数据 |

`qImageToBgr()` 先 `convertToFormat(Format_RGB888)`，用 `bytesPerLine()` 当行步长包一层 `Mat`，再 `COLOR_RGB2BGR`。漏掉通道转换时，蓝牌在算法眼里是红牌，HSV 色相对不上，颜色筛选会整路失效。漏掉行步长时，图像底部会花屏或斜切。`matToQImage()` 对灰度图用 `Format_Grayscale8`，对彩色图先转 RGB，并且都要 `copy()`。不拷贝的话，函数结束、`Mat` 析构之后，窗口上就是悬空内存。

红框画在和检测用图一样大的 `QImage` 上，坐标是原图像素。显示时的缩放发生在画完框之后，框会跟着图一起等比缩小。

## 参数

全部可调数字在 `client/src/PlateDetector.cpp` 顶部的 `cfg`。改完要重新编译。`kInputMode`、`kCameraIndex` 只是预留，没有人读取。

| 类别 | 常量与当前值 | 作用 |
| --- | --- | --- |
| 预处理 | `kGaussianKsize` 5，`kSobelKsize` 3，`kUseOtsu` 开，大津低于 25 时改用 `kFixedThreshold` 80 | 边缘清晰度 |
| 闭运算 | `kCloseKernelW` 17、`kCloseKernelH` 5、`kCloseIterations` 1；相对 `kRefImageWidth` 1000 按 0.7～1.5 倍缩放 | 字符是否粘成一块 |
| 正对外接矩形 | 宽高比 2.0～5.5，矩形度至少 0.40，倾斜不超过 20°，边缘均值至少 12，宽至少 60、高至少 18 | 正对车牌 |
| 边缘候选底色 | 蓝 `(95,50,40)`–`(140,255,255)`，黄 `(10,70,70)`–`(40,255,255)`，占比至少 0.18 | 去掉车标、镀铬字 |
| 水平颜色块 | 掩码蓝 `(100,80,50)`–`(140,255,255)`，黄 `(15,80,80)`–`(40,255,255)`；占比至少 0.60，宽至少 110、高至少 36、宽不超过图宽 65% | 字符没连成整块时补一块实心牌 |
| 倾斜颜色旋转框 | 宽高比 1.55～4.8，矩形度至少 0.55，底色至少 0.55，边缘均值至少 8，长边至少 100 且不超过图宽 48%，短边至少 28，倾斜不超过 50°，框顶 `y` > 12 | 小牌和侧拍 |
| 倾斜边缘旋转框 | 二值阈值至少 `kEdgeBinaryFloor` 60；宽高比 2.0～5.2，矩形度至少 0.32，宽松底色至少 0.32，边缘均值至少 18，长边至少 100 且不超过图宽 45%，倾斜不超过 42° | 夜间反光、蓝车身 |
| 重叠抑制 | `kNmsIou` 0.30，`kMaxPlates` 3 | 同一张牌只留一个框 |

倾斜边缘块使用的宽松底色是蓝 `(95,35,35)`–`(140,255,255)`、黄 `(12,60,60)`–`(40,255,255)`。它比水平颜色块松，只用于已经具备车牌形状的边缘块。

这些数是在挡具体的误检，不要只朝「多检出几张」那一边放宽：

| 看到的现象 | 参数在挡什么 | 不要随便往哪边改 |
| --- | --- | --- |
| 车标、镀铬 “CITY” 被当成牌 | `kMinEdgeColorRatio = 0.18` | 再降低，车标会回来 |
| 车灯里一小块蓝高光被当成牌 | 颜色块最小宽 110、高 36；旋转框长边至少 100 | 为了极小的牌把长边降到 70 左右，车灯容易进来 |
| 中网被粘成一条横牌 | 旋转长边不超过图宽的 48%（边缘路径是 45%） | 放宽之前先看掩码是不是已经和中网粘住 |
| 挡风玻璃顶上一小条蓝反光得分很高 | 框的顶边 `y` 必须大于 12 | 删掉这条，反光框会压过真牌 |
| 地面纸片、斜牌子形状不够方 | 倾斜颜色块矩形度至少 0.55 | 降到 0.4 附近，地面杂块会进来 |
| 远处小牌的旋转宽高比只有 1.66 | `kMinRotatedAspect = 1.55` | 再降，接近正方形的蓝车身碎片会进来 |
| 夜间大津阈值只有十几，整车粘成一块 | `kEdgeBinaryFloor = 60` | 降回和普通大津一样，夜间图会再次粘死 |
| 蓝车身把同色车牌吞进去 | 改靠字符边缘，颜色占比只要 0.32 | 把 0.32 降到接近 0，中网和深色缝隙会进来 |
| 同一张牌两个框 | IoU 0.30，再加上「中心落在已选框内」 | 只放宽 IoU 而不看中心，内嵌的小框还会留下 |
| 字符之间的缝没补上 | 闭运算宽核，样图上 1 次就够 | 默认改成 2 次会把牌和车灯粘在一起 |
| 字符被切掉一条边 | `kRoiPadding = 8`，倾斜框再向外 8% | 扩太多会把保险杠带进 ROI |

颜色用 HSV 而不是直接在 BGR 上比蓝色，是因为 HSV 把「是不是蓝」和「有多亮」拆开了。OpenCV 里 H 的范围是 0～180。饱和度用来区分真正的蓝漆和发灰的反光。夜间路径才把饱和度下限从 80 降到 35，并且只允许已经像车牌的边缘块使用这套松条件。

核宽跟着整张图的宽度走，不跟着车牌在图里的像素宽度走。车离镜头远近变化很大时，同一个 17 像素不一定刚好跨过两个字符的间隙。

## 结果不对时怎么看

点「查看边缘与掩码」。里面是垂直边缘、二值图和闭运算掩码，三张都来自正对那条边缘路径，不是颜色掩码。一次只改一个量。

1. **垂直边缘。** 字符应是清楚的竖白线。发虚就把 `kGaussianKsize` 调到 3（保持奇数）。全图都是密麻点就把高斯核调到 7，或提高阈值。只有车身轮廓、没有字符，是这张图的字符对比度不够。
2. **二值图。** 字符竖线断开就降低 `kFixedThreshold`，或继续用大津法。背景成片变白就提高 `kFixedThreshold`，并把 `kUseOtsu` 设为 `false`。
3. **闭运算掩码。** 一副车牌应变成一个白色横条。仍是多根细条时增大 `kCloseKernelW`，或把 `kCloseIterations` 调到 2。白块吞进中网、车灯时减小核宽，迭代改回 1。不要把迭代次数默认改成 2。图像远宽于 1000 像素、车牌又很小时，把 `kScaleKernelWithImage` 设为 `false`，再按字符间隙手调核宽。间隙大约 N 像素时，核宽取略大于 N 的奇数。
4. **框的位置。** 框住了字符但边缘被切掉，增大 `kRoiPadding`。假框很多时把正对宽高比收到约 2.6～4.2，并提高 `kMinExtent` 或底色占比下限。侧拍漏检时，先看颜色掩码里牌面是否还是独立一块；是的话再放宽 `kMinRotatedLongSide`、`kMinRotatedAspect` 或 `kMaxRotatedTiltDeg`。颜色块已经和车身粘在一起时，再看 `kEdgeBinaryFloor` 和 `kEdgeRotatedMinPaint`。

显示上的常见错法：蓝牌在画面里变成红色，是 BGR 和 RGB 反了；图像底部花屏或斜切，是构造 `Mat` 时没有使用 `QImage::bytesPerLine()`；原图被拉扁，是显示没用 `Qt::KeepAspectRatio`。

建议先打开 `samples/demo_synthetic.bmp`。它应该出现一个红框和一张 ROI，左侧竖杆不应被框住。

## 方法本身的边界

这套方法利用的是「字符竖线多、蓝/黄底色、闭运算后接近 3:1 的矩形」，没有车牌语义。当前 `samples/` 里的合成图和 10 张实车图都能框在牌上，换一批照片仍会遇到下面的情况。

- 模糊、强反光、污损、遮挡会让竖线断开或底色破碎，从而漏检。广告横幅、蓝色店招、带字的纸箱，只要同时满足这三条，也会被框住。
- 闭运算核只随整张图宽度稍微缩放，不随车牌真实像素宽度变化。比 `sample_10.jpg` 更小的牌，旋转宽高比会掉到 1.55 以下。牌特别大时，核又相对太窄或太宽。
- 夜间反光和蓝车身靠字符边缘补检。框内蓝/黄像素太少，或者字符边缘被尾灯淹没时，仍然会漏。阈值 60、颜色占比 0.32 是对着现有样图定的。
- 牌被画面裁掉一半，或者贴在画面左、右边缘时会被丢掉。这条是为了去掉车身边缘的误检，真牌贴边也会一起被丢。
- 颜色旋转框倾斜超过 50°、边缘旋转框倾斜超过 42°，或者框顶贴在画面最上沿时直接丢弃。最上沿这条是为了挡住挡风玻璃反光。
- `warpPlate()` 按 y 坐标分上下两边。牌接近竖着、或者四个角的上下关系因为强透视搞反时，拉出来的 ROI 仍是斜的。
- 规则按单行蓝牌设置。双层黄牌宽高比接近 1～2，会被当成太方。摩托牌更小。新能源绿牌色相不在现在的蓝/黄范围里，只有形状特别标准时才可能被边缘路径撞上。绿色范围如果要加，必须和树、草地的面积上限一起用。
- 调试窗口看不到颜色掩码。调颜色阈值时，现在只能改数字再看最终框。
- 参数全部是编译期常量。一次只改一个常量，并用 `samples/` 里那 11 张图回归。
