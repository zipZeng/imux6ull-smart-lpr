# 车牌定位（Qt 界面）

用 Qt6 选择车辆图片，底层是 OpenCV 4.10 的传统定位：只画车牌框、裁剪 ROI，不做 OCR，也不用深度学习。

算法在 `src/PlateDetector.h` / `src/PlateDetector.cpp`，不包含任何 Qt 头文件。界面在 `MainWindow`，负责选图、颜色转换和显示。

## 目录

```
CMakeLists.txt              Qt6 + OpenCV 4.10
src/PlateDetector.h         检测结果和算法类声明
src/PlateDetector.cpp       预处理、轮廓筛选、颜色与倾斜补检，参数在文件顶部 cfg
src/mainwindow.h
src/mainwindow.cpp          选图、Mat/QImage 转换、红色框和缩放显示
src/mainwindow.ui
src/main.cpp                只启动窗口，不读命令行图片路径
docs/调试排错清单.md         编译、显示、定位常见问题
images/demo_synthetic.bmp   合成车牌，确认界面和算法是否连通
images/sample_*.jpg         实车样图，均为 720×1160
```

生成目录是 `build/`。请打开 CMake 生成的解决方案 `build/LicensePlateDetector.sln`，不要再编译原来的控制台工程。

## 编译

本机路径已经写在 `CMakeLists.txt`：

- Qt：`F:\software\Qt\6\6.9.3\msvc2022_64`（必须是 MSVC 套件，不要用 `mingw_64`）
- OpenCV：`D:\Project\QT\Opencv_operatorVideo\third_party\opencv\build`（4.10.0，`opencv_world4100`）

在工程根目录执行：

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

也可以用 VS2022 打开 `build/LicensePlateDetector.sln`，配置选 **Release | x64** 后生成。平台必须是 x64。

生成后事件会把 `opencv_world4100.dll` 复制到 exe 旁边，并运行 `windeployqt`。直接启动：

```bat
build\Release\LicensePlateDetector.exe
```

若链接时报 `LNK1104`（无法打开 exe），先关掉正在运行的 `LicensePlateDetector.exe`，再重新生成。`windeployqt` 提示找不到 `VCINSTALLDIR` 时可以忽略，Qt DLL 仍会部署到 exe 旁边。

## 运行

1. 点击 **选择图片**，选 bmp、jpg、jpeg 或 png。加载失败会弹出提示。
2. 图片读入后自动定位。
3. 找到车牌：左侧原图出现红色框（正对时为矩形，侧拍倾斜时为四边形），右侧显示裁剪出的 ROI，状态为 **✅检测到车牌**。多张候选时全部画框，右侧显示得分最高的一张。
4. 没找到：左侧仍显示原图，右侧写 **未检测到车牌**，状态为 **❌未检测到车牌**。
5. **查看边缘与掩码** 打开垂直边缘、二值图和闭运算掩码，用来调参。图片按 `QLabel` 大小等比缩放，不会拉变形。

窗口打开时状态是 **请选择车辆图片**。选图前 **查看边缘与掩码** 是灰的。检测失败或 OpenCV 抛异常时会弹出提示。

可以先选 `images\demo_synthetic.bmp`。这张合成图应出现一个红框和一张 ROI。

## 定位流程

`locatePlate` 把下面几路候选合并，再按得分做重叠抑制。最多保留 3 个框。两个框的 IoU 超过 0.30，或者低分框的中心落在高分框向四周扩 1/5 的范围内，只留分高的那个。

1. **边缘轮廓**：灰度 → 高斯 → 垂直 Sobel → 二值化 → 小核开运算 → 闭运算 → 外轮廓。按面积、外接矩形宽高比 2.0～5.5、矩形度、倾斜角和边缘强度筛选。正对、字符能粘成横条的牌走这条，例如 `sample_0.jpg` 和合成图。
2. **底色过滤**：在候选框内统计蓝牌、黄牌 HSV 占比。边缘候选至少 0.18，用来去掉车标和镀铬字。
3. **水平颜色块**：字符没粘成整块时，用蓝/黄掩码再找一块实心横条。正对的本田 `sample_1.jpg` 走这条。
4. **倾斜颜色块**：侧拍或小牌用 `minAreaRect`。旋转宽高比可以低到 1.55，所以远处丰田小牌也能留下。界面画四边形，ROI 做透视矫正；矫正后若高度大于宽度，再顺时针转 90°。
5. **倾斜边缘块**：夜间反光或蓝车身把底色拆开、吞进车身时，用较高阈值的字符边缘再找旋转矩形，并要求框内仍有一定蓝/黄像素。夜间奥迪和蓝色沃尔沃走这条。贴在画面左、右边缘的块会被丢掉。

算法内部标注图是绿色框。界面用 `QPainter` 另画红色框，不使用算法标注图。

## Mat 与 QImage

转换写在 `MainWindow`，不放进 `PlateDetector`。

- Qt 的 `Format_RGB888` 字节顺序是 R、G、B。OpenCV 彩色图是 B、G、R。送进算法前用 `cv::COLOR_RGB2BGR`，显示前用 `cv::COLOR_BGR2RGB`。漏掉这一步时，蓝牌会变成红牌。
- `QImage` 每一行可能按 4 字节对齐，`bytesPerLine()` 往往大于 `width * 3`。构造 `cv::Mat` 时必须把这个值传给 `step`，不能假设图像内存连续。
- `QImage::bits()` 指向的内存在 `QImage` 销毁后失效。`cvtColor` 会分配新的 `Mat`；从 `Mat` 构造 `QImage` 后必须 `copy()`，否则窗口里会是悬空内存。
- 灰度边缘图和掩码用 `Format_Grayscale8`，同样要 `copy()`。
- 倾斜候选带四个角点时，界面画多边形；正对候选画矩形。

## 调参

参数都在 `src/PlateDetector.cpp` 的 `cfg`。改完重新编译。

| 类别 | 常量与当前值 | 作用 |
| --- | --- | --- |
| 预处理 | `kGaussianKsize` 5，`kSobelKsize` 3，`kUseOtsu` 开，大津低于 25 时改用 `kFixedThreshold` 80 | 边缘清晰度 |
| 闭运算 | `kCloseKernelW` 17、`kCloseKernelH` 5、`kCloseIterations` 1；相对 `kRefImageWidth` 1000 按 0.7～1.5 倍缩放 | 字符是否粘成一块 |
| 正对外接矩形 | 宽高比 2.0～5.5，矩形度 ≥ 0.40，倾斜 ≤ 20°，边缘均值 ≥ 12，宽 ≥ 60、高 ≥ 18 | 正对车牌 |
| 边缘候选底色 | 蓝 `(95,50,40)`–`(140,255,255)`，黄 `(10,70,70)`–`(40,255,255)`，占比 ≥ 0.18 | 去掉车标、镀铬字 |
| 水平颜色块 | 掩码蓝 `(100,80,50)`–`(140,255,255)`，黄 `(15,80,80)`–`(40,255,255)`；占比 ≥ 0.60，宽 ≥ 110、高 ≥ 36、宽不超过图宽 65% | 字符没连成整块时补一块实心牌 |
| 倾斜颜色旋转框 | 宽高比 1.55～4.8，矩形度 ≥ 0.55，底色 ≥ 0.55，边缘均值 ≥ 8，长边 ≥ 100 且不超过图宽 48%，短边 ≥ 28，倾斜 ≤ 50°，框顶 `y` > 12 | 小牌和侧拍 |
| 倾斜边缘旋转框 | 二值阈值至少 `kEdgeBinaryFloor` 60；宽高比 2.0～5.2，矩形度 ≥ 0.32，宽松底色 ≥ 0.32，边缘均值 ≥ 18，长边 ≥ 100 且不超过图宽 45%，倾斜 ≤ 42° | 夜间反光、蓝车身 |
| 重叠抑制 | `kNmsIou` 0.30，`kMaxPlates` 3 | 同一张牌只留一个框 |

倾斜边缘块使用的宽松底色是蓝 `(95,35,35)`–`(140,255,255)`、黄 `(12,60,60)`–`(40,255,255)`。它比水平颜色块松，只用于已经具备车牌形状的边缘块。

`kInputMode`、`kCameraIndex` 只是预留，界面没有接摄像头。

一次只改一个量，然后看 **查看边缘与掩码**：

1. 垂直边缘里，字符应是清楚的竖白线。发虚就减小 `kGaussianKsize`（保持奇数）。噪点很多就加大高斯核，或提高阈值。
2. 二值图里，字符应是断开的白条。断得太碎就降低 `kFixedThreshold`，或继续用大津法。背景成片变白就提高阈值，并把 `kUseOtsu` 设为 `false`。
3. 掩码里，一副车牌应变成一个白色横条。仍是多根细条时增大 `kCloseKernelW`，或把 `kCloseIterations` 调到 2。白块吞进中网、车灯时减小核宽或迭代次数。不要把迭代次数默认改成 2，合成图和实车图都会把牌和车灯粘到一起。
4. 框切到字符时增大 `kRoiPadding`。误检多时把正对宽高比收到约 2.6～4.2，并提高 `kMinExtent` 或底色占比下限。
5. 侧拍漏检时，先看颜色掩码里牌面是否还是独立一块。是的话再放宽 `kMinRotatedLongSide`、`kMinRotatedAspect` 或 `kMaxRotatedTiltDeg`。颜色块已经和车身粘在一起时，再看倾斜边缘块的 `kEdgeBinaryFloor` 和 `kEdgeRotatedMinPaint`。

核宽会按图像宽度相对 1000 像素做 0.7～1.5 倍缩放。车牌在大图里很小时，把 `kScaleKernelWithImage` 设为 `false`，再按字符间隙手调 `kCloseKernelW`。

原理、每个函数的输入输出，以及 Qt 和 OpenCV 怎么交接，见 `docs/项目原理说明.md`。编译和显示上的排错见 `docs/调试排错清单.md`。

## 传统方案的局限

这套方法利用的是「字符竖线多、蓝/黄底色、闭运算后接近 3:1 的矩形」，没有车牌语义。

- 模糊、强反光、污损、遮挡会让竖线断开或底色破碎，从而漏检。
- 闭运算核太窄，字符粘不到一起；太宽，会和中网、车灯粘成一块。
- 核大小只随整张图宽度轻微变化，不随车牌真实像素宽度变化。比 `sample_10.jpg` 更小的牌，旋转宽高比会掉到 1.55 以下。
- 夜间反光和蓝车身靠字符边缘补检。框内蓝/黄像素太少，或者字符边缘被尾灯淹没时，仍然会漏。
- 牌被画面裁掉一半，或者贴在画面左、右边缘时，长宽比和边缘约束对不上，会被丢掉。
- 颜色旋转框倾斜超过 50°、边缘旋转框倾斜超过 42°，或者框顶贴在画面最上沿时直接丢弃。最上沿这条是为了挡住挡风玻璃反光。
- 规则按单行蓝牌设置。双层黄牌、摩托牌不在可靠范围内。新能源绿牌约 3.43，有时会被同一组阈值框到。
