# Qt + OpenCV 4.10 车牌定位：原理说明

这份说明面向正在学 C++ / Qt / OpenCV 的人。它讲的是当前工程里真实在跑的代码：只定位车牌、画出框、裁出车牌小图，不识别车牌上的字，也不使用深度学习。

国内小型汽车蓝牌大约 440 mm × 140 mm，宽高比约 3.14。算法就抓住三件事：字符有很多竖笔画、牌底是蓝色或黄色、整体接近一块横向矩形。侧着拍、夜里反光、车身也是蓝色时，这三件事不会同时成立，所以代码里准备了几条互补的找牌路径。

---

## ① 项目简介

程序是一个 Windows 桌面窗口。你选一张 bmp、jpg 或 png，窗口左边显示原图并画上红框，右边显示裁下来的车牌，上方文字变成「✅检测到车牌」或「❌未检测到车牌」。

它分成两层，中间只通过 OpenCV 的 `cv::Mat` 传图：

| 层 | 放在哪 | 知道什么 | 不知道什么 |
| --- | --- | --- | --- |
| 界面层 | `main.cpp`、`mainwindow.*` | Qt 窗口、文件对话框、`QImage`、怎么把图画到标签上 | 高斯模糊、轮廓、宽高比这些算法细节 |
| 算法层 | `PlateDetector.h`、`PlateDetector.cpp` | 怎么从一张 BGR 图里找出车牌框和裁剪图 | Qt、窗口、按钮。这个头文件里甚至不能出现 Qt 头文件 |

这样拆的好处是：算法可以单独拿一张 `cv::Mat` 来测，以后如果要改成摄像头逐帧调用，也不用改界面类里的按钮逻辑。现在界面还没有接摄像头。`cfg` 里的 `kInputMode`、`kCameraIndex` 只是预留，没有人读取它们。

算法类只有四个对外函数：

- `locatePlate()`：给一张图，返回找到没有、框在哪、裁剪图是什么。
- `preProcess()`：把彩色图变成「字符竖线粘成横条」的黑白掩码。
- `getPlateContours()`：在这张掩码上找轮廓，按几何规则留下像车牌的块。
- `drawAndCropPlate()`：在图上画绿框，并裁出车牌小图。

界面不会把绿框那张图显示出来。窗口上的红框是 `MainWindow` 用 `QPainter` 自己画的。

### CMake 要点

脚本做了这几件事：

1. 要求 C++17。`std::clamp`、结构化绑定这些写法需要它。
2. 用 `QT_ROOT` 指向 Qt 6.9.3 的 **MSVC 2022 x64** 套件。旁边那个 `mingw_64` 不能和这份 VS 工程、OpenCV 的 `vc16` 库混用。
3. 用 `OpenCV_DIR` 指向 OpenCV 4.10 的 `build` 目录，里面有 `OpenCVConfig.cmake`。链接的是 `opencv_world4100`（Debug 是 `opencv_world4100d`）。
4. `qt_add_executable(... WIN32 ...)` 把界面源文件和算法源文件打进同一个 exe，并且是窗口程序，双击不会闪一个黑控制台。
5. MSVC 打开 `/utf-8`，源文件里的中文字符串才能按 UTF-8 编译。
6. 生成之后复制 `opencv_world4100.dll`，再调用 `windeployqt`，把 `Qt6Widgets.dll`、`platforms/qwindows.dll` 等放到 exe 旁边。所以 `build\Release\LicensePlateDetector.exe` 可以直接双击。

换电脑时只改 `CMakeLists.txt` 里的 `QT_ROOT` 和 `OpenCV_DIR`，然后重新配置：

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

平台必须是 x64。如果链接报 `LNK1104`，通常是窗口还开着，exe 被占用。先关掉程序再生成。`windeployqt` 提示找不到 `VCINSTALLDIR` 可以忽略，DLL 仍然会拷过去。

### 怎么运行

1. 启动 `build\Release\LicensePlateDetector.exe`。
2. 点 **选择图片**。取消对话框则什么都不做。
3. 读入成功后自动检测。左边是原图，右边是车牌 ROI。
4. 点 **查看边缘与掩码**，看垂直边缘、二值图、闭运算掩码。这三张都来自正对车牌那条边缘路径，不是颜色掩码。
5. 建议先打开 `images\demo_synthetic.bmp`。它应该出现一个红框和一张 ROI。

## ③ 整体架构

### 类和数据

界面这边：

- `main()` 创建 `QApplication` 和 `MainWindow`，然后进入 Qt 事件循环。它不读命令行图片路径。
- `MainWindow` 持有一个 `PlateDetector detector_`。按钮信号接到 `onSelectImage()`、`onViewDebug()`。
- 成员里缓存了五张 `QImage`：画好红框的原图、ROI、边缘图、二值图、掩码。窗口缩放时用这些缓存重画，不用重新检测。

算法这边，对外是 `PlateDetector`，对内还有一组不进头文件的辅助函数，都写在 `PlateDetector.cpp` 的匿名命名空间里。界面调用不到它们，这是故意的。

在两层之间传递的是四个结构体，都只含 OpenCV 类型：

| 结构体 | 干什么 |
| --- | --- |
| `PlateCandidate` | 一个候选：外接矩形、四个角点（侧拍才有）、面积、宽高比、矩形度、边缘强度、倾斜角、得分 |
| `PreprocessResult` | 灰度图、边缘图、二值图、闭运算掩码，以及实际用了多大的核、多高的阈值 |
| `LocateResult` | 一次检测的全部结果：候选列表、裁剪图、中间图、成功还是失败 |
| `FilterStats` | 轮廓一共多少、因为面积 / 尺寸 / 宽高比 / 矩形度 / 倾斜 / 边缘被丢掉多少。方便对着中间图调参 |

### 谁调用谁

```
用户点击「选择图片」
        │
        ▼
MainWindow::onSelectImage          Qt：对话框、QImage::load
        │  qImageToBgr()            Qt → OpenCV，得到 BGR 的 Mat
        ▼
PlateDetector::locatePlate         算法入口，不认识 Qt
        │
        ├── preProcess             灰度、模糊、Sobel、二值化、开运算、闭运算
        ├── getPlateContours       在边缘掩码上按「正对矩形」筛选
        ├── keepPaintedPlates      框里蓝/黄不够就丢掉（挡住车标）
        ├── plateColorMask
        │     └── getPlateContours 在颜色掩码上再找一块水平实心牌
        ├── findTiltedColorPlates  侧拍、小牌：按旋转矩形找蓝/黄块
        ├── findTiltedEdgePlates   夜间、蓝车身：按字符边缘找旋转矩形
        ├── suppressOverlap        重叠的只留分高的，最多 3 个
        └── drawAndCropPlate       绿框标注图 + 裁剪 / 透视矫正 ROI
        │
        ▼
LocateResult（仍是 Mat）
        │
        ▼
MainWindow::showDetection          QPainter 画红框；matToQImage 显示 ROI
```

注意这条边界：`PlateDetector.h` 只 `#include <opencv2/opencv.hpp>`。`MainWindow` 可以包含 `PlateDetector.h`，算法文件不能包含 `QImage`、`QWidget`。颜色转换函数 `qImageToBgr`、`matToQImage` 是 `MainWindow` 的私有静态函数。

## ④ 从打开图片到窗口上看到框

下面按一次成功检测的时间顺序走。括号里是真正被调用的函数。

**1. 选文件（界面）**

`QFileDialog::getOpenFileName` 只接受 `*.bmp *.jpg *.jpeg *.png`。用户取消就直接返回。Qt 的对话框本身支持中文路径，所以算法不用自己处理宽字符文件名。

**2. 读进内存（界面）**

`QImage::load`。失败就弹出「无法打开图片」，不会进入算法。空图同样拦截。

**3. 变成 OpenCV 要的 BGR（界面）**

`qImageToBgr`：先转成 `Format_RGB888`，用 `bytesPerLine()` 当行步长包一层 `Mat`，再 `cv::COLOR_RGB2BGR`。`cvtColor` 会分配一块新内存，所以返回的 `Mat` 不依赖那张临时 `QImage`。

**4. 算法入口（算法）**

`locatePlate` 先检查 `cfg` 是否自相矛盾（高斯核必须是奇数、宽高比上下限不能反了等），再拒绝空图和过小的图。

**5. 预处理（算法）**

`preProcess` 得到四张图：灰度、垂直边缘、二值图、闭运算掩码。掩码上，理想情况是「一副车牌变成一条白色横块」。

**6. 第一条找牌路径：正对的边缘轮廓（算法）**

`getPlateContours` 在掩码上找外轮廓，丢掉太小、太偏、太斜、里面没有竖笔画的块。然后再用 `keepPaintedPlates`，要求框内蓝色或黄色像素至少占 18%。本田车尾的镀铬 “CITY” 竖线很多、形状也像一块牌，但几乎没有蓝底，就在这里被丢掉。蓝色现代那张正对的牌走通的是这一条。

**7. 第二条：水平颜色块（算法）**

字符间隙太大、闭运算没把整块牌粘上时，边缘路径会只看到半块牌或什么都看不到。`plateColorMask` 先把蓝底、黄底涂成白色，再闭运算把白字留下的洞补上。然后仍调用同一个 `getPlateContours`。这一路额外要求更「实心」：颜色占比至少 60%，宽至少 110、高至少 36，并且不能宽到占满大半张图。正对本田那张牌走的是这一条。

**8. 第三条：倾斜颜色块（算法）**

车是侧着拍的时候，车牌在图片上不再是水平长条。一个 3:1 的牌子转 20° 以后，水平外接矩形的宽高比会掉到 2.0 以下，第一条、第二条的「宽高比 2.0～5.5」会把它判掉。`findTiltedColorPlates` 改用 `minAreaRect`，量的是旋转之后的长边和短边。远处丰田小牌、别克、大众、金色轿车走的是这一条。

**9. 第四条：倾斜边缘块（算法）**

夜里尾灯一照，蓝底饱和度下降，颜色掩码是碎的。车身本身是蓝色时，颜色掩码又会把车牌和保险杠吞成一大块，形状完全不像牌。`findTiltedEdgePlates` 改去更高阈值的字符边缘上找旋转矩形，同时仍要求这块里面有一些蓝或黄，避免把中网、车标捡回来。夜间奥迪和蓝色沃尔沃走的是这一条。

**10. 合并（算法）**

四路结果放进同一个数组。`suppressOverlap` 按得分从高到低挑：两个框重叠太多，或者低分框的中心落在高分框里面，就丢掉低分的。最多留 3 个。这样同一张牌不会画出两个框。

**11. 裁剪（算法）**

`drawAndCropPlate`。正对的牌直接把矩形四周扩 8 像素再 `clone`。侧拍的牌把四个角从中心向外撑 8%，做透视变换，拉成一张横着的小图。如果拉完发现高度比宽度大，再顺时针转 90°。界面右边显示的就是这个小图里得分最高的一张（数组里的第一张，因为前面已经按得分排序过）。

**12. 画回窗口（界面）**

`showDetection` 不使用算法画的那张绿框图。它在原始 `QImage` 上用红笔再画一遍：有四个角点就画多边形，否则画矩形。ROI 用 `matToQImage` 转回去。状态文字和颜色在这里设置。

**13. 缩放（界面）**

`paintLabel` 用 `Qt::KeepAspectRatio` 放进 `QLabel`。窗口大小变了只重画缓存，不重新跑算法。

没找到牌时，算法仍然返回一张和原图一样大的标注图（上面没有框），`rois` 为空。界面据此显示原图、右侧写「未检测到车牌」、状态为「❌未检测到车牌」。

## ⑤ 每个函数在做什么

先讲原理，再对应代码里的名字。算法文件顶部的 `cfg` 是全部可调数字，函数体里尽量不再写死另一套阈值。

### 界面函数

**`main`**

创建应用和窗口，窗口初始 1120×720，然后 `app.exec()` 进入事件循环。没有图片参数。

**`MainWindow` 构造函数**

`setupUi` 读 `.ui` 文件。两个预览标签设成深色背景、内容居中、随窗口拉伸。状态文字字号 16。把两个按钮的 `clicked` 接到槽函数。此时还没有图，调试按钮是灰的。

**`onSelectImage`**

对话框 → `QImage::load` → `qImageToBgr` → `detector_.locatePlate` → `showDetection`。OpenCV 抛 `cv::Exception` 时弹「OpenCV 异常」，避免程序直接崩掉。`result.ok == false` 时弹 `result.error`，例如图太小、参数不合法。

**`showDetection`**

输入是原始 `QImage` 和 `LocateResult`。它把原图转成 RGB888，找到牌就用红色 `QPainter` 遍历 `result.plates`。线宽大约是图宽的 1/300，至少 2 像素。然后把 ROI、边缘、二值、掩码都转成 `QImage` 存进成员。`result.rois.front()` 是得分最高的那张裁剪图。最后改状态文字并 `refreshViews()`。

**`onViewDebug`**

弹出一个 1440×560 的对话框，三列分别是「垂直边缘」「二值图」「二值掩码」。每张图缩到 500×460，保持比例。没选过图就提示「请先选择一张图片」。

**`refreshViews` / `paintLabel`**

没图时显示占位文字：左边「尚未选择图片」，右边在检测前是「等待检测」、检测后没牌是「未检测到车牌」。有图就 `scaled(..., KeepAspectRatio)`。标签还没布局出大小时（宽或高小于 2）先不画，等 `showEvent` / `resizeEvent` 再画。

**`resizeEvent` / `showEvent`**

只调用 `refreshViews()`，不重新检测。

### 预处理：`preProcess`

输入：一张 `Mat`，可以是灰度、BGR 或 BGRA。输出：`PreprocessResult`。失败时 `ok == false`，`error` 里有原因。图宽或高小于 32 直接拒绝。

内部按这个顺序做，每一步都有明确目的：

1. **统一成灰度。** 车牌定位先不看颜色，颜色留到后面专门筛蓝底、黄底。3 通道走 `BGR2GRAY`，4 通道走 `BGRA2GRAY`。
2. **高斯模糊，核 5×5。** 减弱树叶、地面颗粒这类细噪点。核越大，字符笔画也越糊，所以没有用很大的核。
3. **垂直 Sobel，`dx=1, dy=0`，核大小 3。** 只响应左右方向的亮度跳变。汉字和字母的竖笔画会产生很强的响应，车身大面积平滑区域几乎没有。先用 `CV_16S` 是因为梯度有正有负，再用 `convertScaleAbs` 收成 0～255 的边缘图。水平方向的车缝、路沿在这张图上会弱很多。
4. **二值化。** 默认大津法，让阈值跟着这张图的亮度走。如果大津算出来低于 25，说明边缘图几乎全黑、直方图太偏，自动改用固定阈值 80，避免整张图变成噪点。
5. **3×3 开运算。** 先腐蚀再膨胀，擦掉孤立的小白点，免得后面的闭运算把噪点也粘成一块。
6. **闭运算 = 先膨胀再腐蚀，核大约 17×5，做 1 次。** 核是扁的：横向跨度大，才能把左右相邻的字符补成一条；纵向跨度小，才不容易把车牌和上面的车标、下面的保险杠粘在一起。核宽按图像宽度相对 1000 像素缩放，限制在 0.7～1.5 倍，并强制成奇数。720 宽的样图实际核大约是 13×5。

输出里最重要的是 `mask`。后面的正对轮廓就是在这张图上找的。`edges` 留下来做两件事：调试窗口要显示它；筛选时还要看候选框里面的平均边缘强不强。

### 轮廓筛选：`getPlateContours`

输入：一张二值掩码、一张边缘强度图、原图尺寸，外加一个用来计数的 `FilterStats`。输出：通过几何规则的 `PlateCandidate` 列表，已按得分从高到低排过，并且做了一次框与框的重叠抑制。

对每个外轮廓（`RETR_EXTERNAL`，只要最外层，不要字符内部的洞）：

1. **面积。** 同时看绝对像素和占整图的比例，取更严的那一侧。太小的是噪点或单个字符，太大的是车身、地面。`findContours` 会改输入图，所以先 `clone`。
2. **外接矩形尺寸。** 宽至少 60、高至少 18，宽不超过图宽的 80%，高不超过图高的 55%。车牌再小，字符也粘不成稳定的块。
3. **宽高比 = 宽 / 高，必须在 2.0～5.5。** 标准蓝牌约 3.14。下限留给轻微透视，上限留给比较窄的远景牌。竖着的灯条、接近正方形的车标过不了这一关。这里用的是不旋转的外接矩形，所以明显侧拍的牌往往在这里被淘汰，交给后面的旋转框路径。
4. **矩形度 = 轮廓面积 / 外接矩形面积，至少 0.40。** 闭运算之后轮廓边缘是毛糙的，不会是完美的四个顶点，所以不要求「一定是四边形」。矩形度太低说明这是一串断开的笔画，或者一条弯弯曲曲的边，不像实心车牌。
5. **倾斜角，不超过 20°。** `minAreaRect` 给出的角度定义比较别扭：OpenCV 把矩形的一条边当宽度，角度范围大约在 -90°～0°。`longEdgeTiltDeg` 先判断哪条边是长边，再把角度折到大约 -90°～90°，表示长边相对水平线歪了多少。正对路径只接受接近水平的牌。
6. **边缘均值，至少 12。** 在原边缘图上取这个矩形的平均亮度。没有字符的横条、纯色反光，边缘均值很低，这里丢掉。

得分大致是：宽高比越接近 3.14 越高（权重 0.55），矩形度越高越好（0.30），边缘越强越好（0.15，超过 40 就封顶）。这一步的得分还没加上颜色分，颜色分在下一步加。

### 去掉车标：`platePaintRatio` 和 `keepPaintedPlates`

`platePaintRatio` 把矩形裁出来，转到 HSV，统计落在蓝色或黄色范围内的像素比例。这里的蓝比后面的「实心颜色块」松一点：色相 95～140，饱和度至少 50，亮度至少 40。黄是色相 10～40，饱和度和亮度至少 70。松一点是为了让边缘路径上的真牌不要因为反光被误杀；真牌只要「沾到蓝」就行。

`keepPaintedPlates` 按调用者给的最低比例过滤。边缘路径要求 0.18，颜色块路径要求 0.60。通过的候选会把 `0.25 * 颜色占比` 加进得分，蓝底更满的排得更靠前。

这就是 “CITY” 被排除的原因。镀铬字母的垂直边缘很强，闭运算后也能变成一块横向区域，宽高比可以落在 2～5.5 里。但它的底是车漆，不是蓝牌，颜色占比接近 0。

### 水平颜色块：`plateColorMask`

整图转 HSV，蓝和黄取并集。蓝是色相 100～140、饱和度 ≥ 80、亮度 ≥ 50；黄是色相 15～40、饱和度 ≥ 80、亮度 ≥ 80。然后用 17×5 的矩形核闭运算，把字符白字在蓝底上抠出的洞补上，再用 5×5 开运算擦掉细碎蓝点。

得到的掩码再送进同一个 `getPlateContours`。回来之后还要删掉太窄（宽 < 110 或高 < 36）、太宽（超过图宽 65%）、贴在图像最顶上的块。太窄是为了躲开车灯里一小块偏蓝的高光；太宽是为了躲开整片蓝车身。

### 倾斜颜色块：`findTiltedColorPlates`

颜色范围和上面一样，但形态学用的是 11×11 椭圆闭运算再加 5×5 椭圆开运算。椭圆核不会强行把块拉成水平条，侧着的牌子还能保持自己的方向。

然后对每个轮廓：

- 面积在「绝对下限」和「不超过 8 万像素、也不超过图面积 8%」之间。
- 旋转后的长边至少 100 像素，不超过图宽的 48%；短边至少 28。长边上限是为了丢掉横跨中网的大块。
- 长边 / 短边在 1.55～4.8。1.55 比正对路径的 2.0 低，因为小牌和强透视会让旋转矩形变「胖」。丰田那张小牌大约是 1.66，就靠这个下限留下来。
- 矩形度至少 0.55，比正对路径更严，避免地面上的纸片、斜条被收进来。
- 在旋转矩形内部（不是外接矩形）再数一次原始蓝/黄像素，至少 55%。这一步能把「形状像牌、但蓝色只沾了一条边」的块去掉。
- 外接矩形的顶边 `y` 必须大于 12。挡风玻璃上沿的蓝色反光曾经比真牌得分还高，用位置把它丢掉。
- 边缘均值至少 8。倾斜牌的笔画在垂直 Sobel 上会弱一些，所以这里比正对路径的 12 低。

四个角点存进 `PlateCandidate::corners`，`hasCorners = true`。界面看到这个标志就画四边形，而不是水平矩形。

### 倾斜边缘块：`findTiltedEdgePlates`

输入仍是预处理产生的边缘强度图，不是那张已经用大津阈值切过的二值图。函数自己再二值化一次：阈值取「大津结果」和 60 里更高的那个。夜间照片的大津阈值可能只有十几，整张图会变成白花花的一块，牌和车尾粘死。固定一个 60 的下限，字符还在，大片弱反光被压掉。

后面同样是 3×3 开运算，再用和预处理一样的扁核做闭运算，把字符连起来。筛选比颜色旋转框松在「实心程度」上（矩形度只要 0.32，因为边缘块中间有字符缝，本来就没那么实），严在形状和边缘上：

- 宽高比 2.0～5.2，倾斜不超过 42°。
- 长边至少 100，不超过图宽的 45%。
- 框内边缘均值至少 18。
- 用一套更松的蓝/黄范围再量占比，至少 32%：蓝的饱和度、亮度只要 35。夜间牌的蓝色被灯光洗淡了，用前面那套「饱和度 ≥ 80」会量成 0。
- 框不能贴在图像左边缘或右边缘（左右各留 2 像素）。曾经有一块车身边缘的蓝色区域被收成牌，这条是专门挡它的。顶边同样要 `y > 12`。

这条路径的得分权重较低，最高也就和一条普通颜色候选差不多。颜色路径已经找到的牌会排在前面；这条路径找到的同一块牌，中心落在前面那个框里，合并时会被删掉。

### 合并：`suppressOverlap`

按得分排序。保留一个候选之前，看它和已经留下的框：IoU 大于 0.30，或者它的中心落在对方框向四周扩大 1/5 的范围内，就认为是同一张牌。最多 3 张。

IoU 是交叠面积除以并集面积。两个框只有一条边挨着时 IoU 很小，不会被当成重复。中心包含是为了处理「一个小框完全落在大框内部，但 IoU 不到 0.30」的情况，侧拍大众曾经出现过这种双框。

### 画框和裁剪：`drawAndCropPlate`、`warpPlate`

正对候选：矩形每边外扩 `kRoiPadding`（8 像素），再和图像边界求交，`clone` 出 ROI。标注图上画绿色矩形。

倾斜候选：四个角先求中心，再从中心向外乘 1.08，避免切掉字符边缘。`warpPlate` 把四个点按 y 分成上面两个、下面两个，再按 x 分成左和右，得到左上、右上、右下、左下。用 `getPerspectiveTransform` 映射到一张宽为长边、高为短边的正矩形，`warpPerspective` 采样。若结果高度大于宽度，说明点的顺序把牌转竖了，再 `ROTATE_90_CLOCKWISE`。

标注图上的文字是 `Plate 1` 这种英文。OpenCV 自带的 Hershey 字体不能画中文，所以没有在图上写「车牌」。

这一张绿框图放在 `LocateResult::annotated` 里。当前界面没有显示它，只借用了框的坐标和 ROI。

### 入口：`locatePlate`

把上面几步按固定顺序串起来，并把中间图抄进 `LocateResult`，供调试按钮使用。`found` 的定义是「至少有一张 ROI」，不是「轮廓筛选计数大于 0」。颜色检查可能把几何上合格的框全部删掉，那时 `found` 仍是 false。

### 其它小函数

- `ensureOdd`：把核尺寸收成不小于下限的奇数。OpenCV 的高斯核、部分结构元素要求奇数。
- `validateConfig`：启动检测前检查参数范围，避免一个手滑的数字让后面的除法或 OpenCV 调用直接失败。
- `rectIou`：两个轴对齐矩形的交并比。
- `longEdgeTiltDeg`：把 `RotatedRect::angle` 换成「长边相对水平线的角度」。

## ⑥ 这些参数为什么是现在这样

国内单行蓝牌的几何原型是 440:140 ≈ 3.14。所有宽高比窗口都围着这个数，而不是围着「任意矩形」。

| 你看到的现象 | 参数在挡什么 | 不要随便往哪边改 |
| --- | --- | --- |
| 车标、镀铬 “CITY” 被当成牌 | 边缘候选颜色占比 `kMinEdgeColorRatio = 0.18` | 再降低，车标会回来 |
| 车灯里一小块蓝高光被当成牌 | 颜色块最小宽 110、高 36；旋转框长边至少 100 | 为了极小的牌把长边降到 70 左右，车灯容易进来 |
| 中网被粘成一条横牌 | 旋转长边不超过图宽的 48%（边缘路径是 45%），颜色占比要高 | 放宽长边上限之前先看掩码是不是已经和中网粘住 |
| 挡风玻璃顶上一小条蓝反光得分很高 | 框的顶边 `y` 必须大于 12 | 删掉这条，反光框会压过真牌 |
| 地面纸片、斜牌子形状不够方 | 倾斜颜色块矩形度 ≥ 0.55 | 降到 0.4 附近，地面杂块会进来 |
| 远处小牌的旋转宽高比只有 1.66 | `kMinRotatedAspect = 1.55` | 再降，接近正方形的蓝车身碎片会进来 |
| 夜间大津阈值只有十几，整车粘成一块 | `kEdgeBinaryFloor = 60` | 降回和普通大津一样，夜间图会再次粘死 |
| 蓝车身把同色车牌吞进去 | 不靠颜色块，改靠字符边缘，并且颜色占比只要 0.32 | 把 0.32 降到接近 0，中网和深色缝隙会进来 |
| 同一张牌两个框 | IoU 0.30，再加上「中心落在已选框内」 | 只放宽 IoU 而不看中心，内嵌的小框还会留下 |
| 字符之间的缝没补上 | 闭运算宽核。样图上 1 次就够 | 默认改成 2 次会把牌和车灯粘在一起 |
| 字符被切掉一条边 | `kRoiPadding = 8`，倾斜框再向外 8% | 扩太多会把保险杠带进 ROI |

面积用了两套限制：绝对像素（至少 800）和占整图比例（至少 0.15%、至多 20%）。只写死像素的话，换一张特别大或特别小的图，同一块牌的命运会变。两套同时生效，取更严的一侧。

颜色用 HSV 而不是直接在 BGR 上比蓝色，是因为 HSV 把「是不是蓝」和「有多亮」拆开了。白天和夜里亮度差很多，色相仍大致落在 100～140（OpenCV 里 H 的范围是 0～180，不是 0～360）。饱和度用来区分「真正的蓝漆」和「发灰的反光」。所以夜间路径才不得不把饱和度下限从 80 降到 35，并且只允许已经像车牌的边缘块使用这套松条件。

预处理核宽跟着图像宽度走，不跟着车牌在图里的像素宽度走。车离镜头远近变化很大时，同一个 17 像素不一定刚好跨过两个字符的间隙。这是传统方法的结构性限制，调参只能减轻，不能消除。

## ⑦ Qt 的图和 OpenCV 的图怎么交接

两边都是「一块内存里的像素」，但约定不一样。

| | QImage | cv::Mat |
| --- | --- | --- |
| 彩色通道顺序 | `Format_RGB888` 是 R、G、B | 彩色默认 B、G、R |
| 一行占多少字节 | 常常按 4 字节对齐，`bytesPerLine()` 可能大于 `宽 × 3` | 用 `step` 表示下一行从哪里开始 |
| 谁拥有内存 | `QImage` 销毁后 `bits()` 作废 | `Mat` 是引用计数，拷贝构造默认共享数据 |

**Qt → OpenCV，函数 `qImageToBgr`：**

1. `convertToFormat(Format_RGB888)`，保证连续的 8 位三通道，并且去掉 alpha。
2. 用这块内存构造 `Mat`，但把 `rgb.bytesPerLine()` 传进去当 `step`。如果假设每行正好是 `宽 × 3`，图像底部会花屏或斜切。
3. `cv::cvtColor(..., COLOR_RGB2BGR)`。这一步会分配新 `Mat`，所以函数返回后，临时 `QImage` 可以销毁。

漏掉第 3 步时，蓝牌在算法眼里是红牌，HSV 的色相完全对不上，颜色筛选会整路失效。

**OpenCV → Qt，函数 `matToQImage`：**

- 单通道（边缘图、二值图、掩码）按 `Format_Grayscale8` 包一层，然后 `copy()`。
- 三通道先 `COLOR_BGR2RGB`，再按 `Format_RGB888` 包一层，然后 `copy()`。
- 四通道走 `BGRA2RGBA`。

`copy()` 是必须的。不拷贝的话，`QImage` 只是指向 `Mat` 的缓冲区；函数结束、`Mat` 析构之后，窗口上就是悬空内存，表现成花屏或随机颜色。

红框不经过 OpenCV 绘制。`showDetection` 在 RGB 的 `QImage` 上用 `QPainter` 画。坐标仍是原图像素坐标，因为检测用的 `Mat` 和这张 `QImage` 宽高一致，没有先缩放再检测。显示时的缩放发生在画完框之后，所以框会跟着图一起等比缩小，不会错位。

## ⑧ 现在的缺陷，以及可以怎么改

这些是方法本身的边界，不是某一张样图没调好。当前 `images/` 里的合成图和 10 张实车图都能框在牌上，但换一批照片仍会遇到下面的情况。

**1. 没有「这是一张车牌」的语义。**

现在只是竖线多、蓝或黄、形状接近 3:1。广告横幅、蓝色店招、带字的纸箱，只要同时满足这三条，就会被框住。对应改进：在 ROI 上增加一层非常轻的校验，例如字符区域应该是 7 个左右的连通块，间距比较均匀。这仍然可以不用深度学习。再往上就是一个专门的车牌检测模型，准确率会高一截，但就离开了这个项目「传统图像处理」的范围。

**2. 闭运算核不认识牌有多远。**

核宽只随整张图的宽度稍微缩放。牌在图里特别小，字符间隙比核还宽，粘不成一条；牌特别大，核又相对太窄或太宽。比丰田样图更小的牌，旋转宽高比会掉到 1.55 以下。改进：先用宽松颜色或边缘找一批候选尺度，再按候选宽度选择核，而不是整张图共用一个核。也可以做图像金字塔，在缩小的图上找大牌、在原图上找小牌。

**3. 夜间和蓝车身靠补丁路径，而不是同一套规则。**

颜色掩码在尾灯下会碎，在蓝车身上会和保险杠粘住，所以又加了「更高阈值的边缘 + 更松的蓝色」。阈值 60、颜色占比 0.32 是对着现有样图定的。灯光再强，字符边缘被白光淹没，这条也会失败。改进：在车牌可能出现的下半部做局部对比度拉伸，再跑边缘；或者用自适应阈值代替全局 60。不要把全局饱和度下限再降到 35 以下，否则中网和阴影会一起进来。

**4. 透视矫正只是把四个角拉平。**

`warpPlate` 按 y 坐标分上下两边。牌接近竖着、或者四个角的上下关系因为强透视搞反时，拉出来的 ROI 仍是斜的，只是比外接矩形好一点。界面上别克那张就能看出还没完全摆正。改进：用长边方向决定「哪条边是车牌的上边」，而不是只按 y 排序；或者在 ROI 里再根据字符底部拟合一条基线做一次旋转。

**5. 左右被画面切掉的牌、贴边的牌会被故意丢掉。**

边缘路径拒绝贴在左、右边缘的框，是为了去掉车身边缘的误检。真牌如果正好被画面裁掉一半，也会一起被丢。改进：贴边时不要一刀切，改成「贴边并且颜色占比低、边缘弱」才丢。

**6. 倾斜角上限是硬切。**

颜色路径超过 50°、边缘路径超过 42° 就不要。再侧的拍照、或者手机横过来但 EXIF 方向没转正的图，会漏。改进：读图时按 EXIF 把方向转正；角度上限可以放宽到 60° 左右，但必须同时提高矩形度和颜色占比，否则斜的中网会进来。

**7. 只可靠地覆盖单行蓝牌。**

双层黄牌的宽高比接近 1～2，会被当成「太方」。摩托牌更小。新能源绿牌色相不在现在的蓝/黄范围里，只有形状特别标准时才可能被边缘路径撞上，不能指望。改进：给黄牌单独放宽宽高比下限，并增加绿色 HSV 范围（色相大约 35～85）。绿色范围一定要和「树、草地」的面积上限一起用，否则背景的树会变成候选。

**8. 调试窗口看不到颜色掩码。**

**查看边缘与掩码** 里的第三张是边缘闭运算的结果。颜色路径、旋转路径的掩码没有送进 `LocateResult`。调颜色阈值时，现在只能改数字再看最终框，看不到「蓝色被收成了什么样」。改进：在 `LocateResult` 里加一张 `colorMask`，调试对话框再加一列。这是界面改动，算法接口要加一个字段，但仍然不用让算法去认识 Qt。

**9. 没有摄像头，也没有批量目录。**

`locatePlate` 已经是「一张图进、一张结果出」，接摄像头只需要界面层写一个定时器：`cv::VideoCapture` 读一帧，转成 `Mat`，调用同一个函数。不要把采集写进 `PlateDetector`。批量检测同样是界面或一个独立小工具去循环文件，算法不用改。

**10. 参数全部编译期常量。**

改一个数字要重新编译。对学习项目这是优点，因为所有阈值都在文件顶部，能看清谁影响谁。如果以后要对比很多组参数，再把 `cfg` 收成一个运行时结构体，由界面上的滑块改写。在那之前，一次只改一个常量，并用 `images/` 里那 11 张图回归，尤其是本田不要回到 “CITY”、大众不要框中网、面包车不要框挡风玻璃。
