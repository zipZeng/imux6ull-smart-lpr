# 调试排错清单

界面版直接运行 `build\Release\LicensePlateDetector.exe`，或在 VS2022 里打开 `build\LicensePlateDetector.sln` 后按 F5。不需要在命令行传图片路径。

点 **选择图片** 后会自动检测。调参时点 **查看边缘与掩码**，里面有垂直边缘、二值图和闭运算掩码。参数在 `src/PlateDetector.cpp` 顶部的 `cfg`，改完要重新编译。

## 编译和启动

| 现象 | 处理 |
| --- | --- |
| CMake 找不到 Qt6 | 确认 `CMakeLists.txt` 里的 `QT_ROOT` 是 `F:\software\Qt\6\6.9.3\msvc2022_64`。这是 MSVC 套件，不要指到 `mingw_64` |
| 找不到 `opencv2/opencv.hpp` 或 OpenCV 版本不对 | `OpenCV_DIR` 应指向 `D:\Project\QT\Opencv_operatorVideo\third_party\opencv\build`，该目录里有 `OpenCVConfig.cmake` |
| 链接错误，无法解析 OpenCV 符号 | 生成配置必须是 **x64**。Release 使用 `opencv_world4100.lib`，Debug 使用 `opencv_world4100d.lib` |
| 双击 exe 提示缺少 `opencv_world4100.dll` 或 `Qt6Widgets.dll` | 重新执行 Release 生成。生成后事件会复制 OpenCV DLL，并调用 `windeployqt`。不要把 Debug 的 exe 和 Release 的 DLL 混用 |
| 窗口一闪就消失，并提示缺少平台插件 | `build\Release\platforms\qwindows.dll` 必须在。重新生成，让 `windeployqt` 再部署一次 |
| 中文编译报错 | 工程已加 `/utf-8`。不要把源文件改成系统 ANSI 后再和 UTF-8 混用 |
| 还在编译根目录旧的 `LicensePlateDetector.sln` | 那个控制台工程已经移除。使用 `build` 目录里 CMake 生成的解决方案 |

## 选图和显示

| 现象 | 处理 |
| --- | --- |
| 弹出「图片加载失败」 | 文件损坏，或扩展名与真实格式不一致。对话框只接受 bmp、jpg、jpeg、png |
| 蓝牌在画面里变成红色，或颜色整体发怪 | `Mat` 和 `QImage` 的通道顺序反了。送入算法前必须是 BGR，显示前必须是 RGB。转换在 `MainWindow::qImageToBgr` 和 `matToQImage` |
| 图像底部花屏、斜切 | 构造 `Mat` 时没有使用 `QImage::bytesPerLine()`，行对齐被忽略了 |
| 原图被拉扁或拉高 | 显示使用 `Qt::KeepAspectRatio`。如果改成 `setScaledContents(true)`，比例会被破坏 |
| 有红框但右侧是空的 | 算法没产出 ROI。红框来自候选矩形；ROI 来自 `LocateResult::rois`。两者应同时出现 |
| 没检测到，但原图正常 | 这是筛选没通过，不是读图失败。打开边缘图和掩码继续看下面的定位步骤 |

## 定位结果不对

按这个顺序看，不要同时改很多参数。

### 1. 垂直边缘

字符位置应当有一排竖白线。

- 几乎全黑：光照太差、车牌太小，或高斯核太大。把 `kGaussianKsize` 调到 3。
- 全图都是密麻点：降噪不够。把高斯核调到 7，或提高二值化阈值。
- 只有车身轮廓、没有字符：这张图的字符对比度不够。换更清晰、更正对车牌的照片。

### 2. 二值图

- 字符竖线断开、缺笔：降低 `kFixedThreshold`，或继续用大津法。大津阈值若低于 `kMinOtsuThreshold`（默认 25），程序会改用固定阈值。
- 背景成片变白：提高 `kFixedThreshold`，并把 `kUseOtsu` 设为 `false`。

### 3. 闭运算掩码

期望看到车牌变成一个白色横条。

- 车牌仍是多根分开的竖条：增大 `kCloseKernelW`（保持奇数），或把 `kCloseIterations` 从 1 改成 2。
- 白块吞进中网、车灯、保险杠：减小 `kCloseKernelW`，迭代改回 1。
- 图像远宽于 1000 像素，车牌又很小：把 `kScaleKernelWithImage` 设为 `false`，再按字符间隙手调核宽。间隙大约 N 像素时，核宽取略大于 N 的奇数。

### 4. 框的位置

- 框住了字符，但边缘被切掉：增大 `kRoiPadding`。框跟着字符连通区域，四周留一点蓝边是正常的。
- 假框很多：把宽高比收到 2.6～4.2，提高 `kMinExtent` 和 `kMinEdgeMean`。默认范围是 2.0～5.5，矩形度下限是 0.40。
- 倾斜的车牌被丢掉：增大 `kMaxTiltDeg`。倾斜很大时，水平外接矩形的宽高比也会失真。

## 建议的回归步骤

1. 启动 `build\Release\LicensePlateDetector.exe`。
2. 选择 `images\demo_synthetic.bmp`。
3. 应出现红框、右侧 ROI，以及 **✅检测到车牌**。左侧竖杆不应被框住。
4. 再换一张真实车辆正脸照片，按边缘、二值图、掩码的顺序调闭运算核。
